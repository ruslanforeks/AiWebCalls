# AiWebCalls

Голосовой AI-агент, который сам обзванивает фермеров, выясняет наличие зерна
и складывает результат в CRM закупщика.

Проект решает конкретную задачу: база в 3000+ контактов по одному региону,
которую сейчас обзванивают вручную.

## Что работает сейчас

**Импорт справочников** — читает выгрузку в Excel, нормализует телефоны,
убирает дубли и отсеивает тех, кому звонить незачем.

**Анализ разговора** — превращает расшифровку звонка в структурированные
данные для карточки: культура, объём, качество, цена, срок, когда перезвонить.

**Голосовой агент** — написан, но требует Linux-сервера (см. ниже).

## Требования к телефонии

Когда дойдём до звонков по SIP, от платформы нужны три вещи. Все три влияют
на деньги, и все три надо оговорить при выборе провайдера.

**1. Определение автоответчика (AMD).** Платформа после ответа слушает пару
секунд и решает, человек это или запись. Записи до бота не доводятся.

Без AMD агент три минуты беседует с автоответчиком по полной стоимости.
На базе в 1683 номера при 12% автоответчиков это 1400 ₽ впустую — восьмая
часть бюджета кампании.

У AMD есть цена: он решает за две-четыре секунды, и живой человек всё это
время слышит тишину после своего «Алло». Часть людей за это время кладёт
трубку. Поэтому нужна платформа, умеющая определять автоответчик
**во время гудков**, а не после ответа, либо асинхронно — не задерживая
соединение с человеком.

**2. Конвейер стартует по факту ответа, а не по факту набора.** Соединение
с распознаванием поднимается вместе с конвейером. Если оно откроется на
гудках, счёт пойдёт за секунды тишины: на той же базе это около 200 ₽.

**3. Тарификация только отвеченных вызовов.** Стандарт для российских
операторов, но проверить стоит: некоторые берут плату за попытку.

## Что дальше

CRM: карточки фермеров, кампании обзвона, история звонков, дашборд, экспорт.
Спроектировано в ТЗ, ещё не собрано.

## Главная находка по реальным данным

Выгрузка по Краснодарскому краю — 3161 строка. После импорта:

| | |
|---|---|
| Импортировано | 3106 |
| Дубликаты по телефону | 36 |
| Без телефона | 19 |
| **Стоит звонить** | **1683** |

Почти половина базы — не поставщики зерна:

| Категория | Сколько | Почему пропускаем |
|---|---|---|
| не сельское хозяйство | 585 | автоперевозки, подшипники, соки |
| переработка | 306 | хлебозаводы, крупозаводы — зерно покупают |
| сады и овощи | 240 | яблоки, персик, черешня |
| животноводство | 154 | зерно нужно на корм, а не на продажу |
| закупщики и элеваторы | 136 | конкуренты и посредники |

Отсев до звонка — это прямая экономия: каждый звонок стоит минут связи,
распознавания и синтеза.

Два случая, где наивная фильтрация ошибётся, и в коде на них есть тесты:

- «производство рисовой крупы» — крупозавод, а не поставщик риса;
- «закупка масличных» — конкурент. Звонок ему не просто бесполезен:
  вы спрашиваете у покупателя зерна, не продаст ли он вам зерно.

Поэтому переработка и закупщики проверяются **раньше** списка культур.

## Архитектура

Голосовой звонок — пять независимых слоёв:

```
транспорт  →  STT  →  LLM  →  TTS  →  транспорт
(микрофон,   (речь    (ведёт  (текст
 потом SIP)  в текст) диалог) в речь)
                        ↓
              после звонка: анализ → CRM
```

Каждый слой заменяется отдельно — все провайдеры собираются в
[services.py](voice-agent/src/grainvoice/services.py) и
[extractors.py](voice-agent/src/grainvoice/extractors.py).

### Провайдеры

| Слой | Сейчас | Почему |
|---|---|---|
| Распознавание | ElevenLabs `scribe_v2_realtime` | Deepgram не открывается из России |
| Разговор | DeepSeek `v4-flash` | Задержка: пауза дольше 1.5 сек — и собеседник переспрашивает «алло?» |
| Синтез | ElevenLabs `eleven_flash_v2_5` | Скорость важнее тембра |
| Анализ | DeepSeek `v4-flash` | На замерах извлекает то же, что `v4-pro`, вдвое быстрее |

Меняются переменными в `.env`, код трогать не нужно. Возврат на Claude —
`LLM_PROVIDER=anthropic`.

Распознаванию подсказывается словарь зерновой торговли — без него
«клейковина» превращается в «клей ковина», «натура» в «на туру».

### Цена

Агент называет цену сам, по прайсу протеина
([prices.py](voice-agent/src/grainvoice/prices.py)):

| Протеин | Рублей за тонну |
|---|---|
| 14 | 13 000 |
| 13,5 | 12 800 |
| 13 | 12 600 |
| 12,5 | 12 400 |
| 12 | 12 200 |

Прайс живёт в коде, а не в тексте промпта, потому что это единственное,
что агент говорит от лица компании — фермер вправе на цифру сослаться.
В промпте её никто не проверяет: модель может округлить или придумать
промежуточное значение. Здесь она под тестами.

Промежуточный протеин округляется **вниз**: 13,2 оценивается как 13,0.
Округление вверх означало бы, что компания платит за качество, которого
в зерне нет, и разницу обнаружат на элеваторе. Ниже 12 прайса нет —
такое зерно оценивает руководитель.

Спрашивается именно протеин, а не клейковина: клейковина у большинства
в норме и цену не определяет.

### Главное правило анализа

Модель заполняет только то, что фермер действительно сказал. Всё остальное
остаётся `null`.

Пустое поле честнее выдуманного: менеджер увидит пропуск и уточнит сам,
а правдоподобную выдумку примет за факт. Результат несёт `confidence` —
ниже 0.5 карточка помечается как требующая проверки.

Проверено на живом разборе: фермер сказал «влажность не мерил» — модель
поставила `null`, а не среднее по региону.

## Запуск

Нужен **Python 3.12+**.

```bash
cd voice-agent
python3.12 -m venv .venv
.venv/bin/pip install -e ".[dev]"
cp ../.env.example ../.env    # заполнить ключи
```

Установка обязательно с `-e .` — без неё `python -m grainvoice.*` не найдёт пакет.

### Импорт справочника

```bash
.venv/bin/python -m grainvoice.cli import файл.xlsx --export контакты.csv
```

Выгружает только тех, кому есть смысл звонить. Флаг `--all` — выгрузить всех.

### Разговор через микрофон

```bash
.venv/bin/python -m grainvoice.local \
  --company "«Заря» ООО" --district "Белоглинский район" --crops "пшеница,подсолнечник"
```

Карточка хозяйства нужна не для красоты. Она решает две вещи сразу:
агент не спрашивает культуру, которая и так записана в базе, а название
района уходит подсказкой в распознавание — без неё «Белоглинский»
слышится как «минский» или «янтарский».

Агент заговорит первым. Ctrl+C завершает разговор и запускает разбор — тем же
путём, которым пойдут настоящие звонки.

Этот режим работает и там, где полный конвейер не собирается: он не тянет
`aiortc` и `cryptography`, у которых нет готовых сборок под Intel Mac.

### Разговор через браузер (WebRTC)

```bash
.venv/bin/python -m grainvoice.bot
```

### Кто решает, что фраза закончилась

Границу реплики определяет сам ElevenLabs, а не Pipecat
(`CommitStrategy.VAD`). Это не мелочь настройки, а выбор архитектуры.

При ручной схеме момент «фраза закончена» решает Pipecat и шлёт команду
на сервер. Две стороны расходятся в оценке: Pipecat закрывает реплику
по своей тишине, а ElevenLabs отказывается принимать огрызок короче
трёх десятых секунды — `Commit request ignored`, после чего рвёт
соединение. В худшем случае финальная расшифровка не приходит вовсе:
черновики идут, а результата нет.

При серверной схеме решение принимает одна сторона — та, у которой есть звук.

Порог тишины задаётся `STT_SILENCE_SECS` (по умолчанию 0.7 с).

Отдельно: `VAD_STOP_SECS` увеличивать нельзя. Кажется, что длинная пауза
спасёт неспешного фермера, но за паузы отвечает не VAD, а Smart Turn —
модель, которая смотрит на смысл сказанного. Она откалибрована под 0.2,
и при большем значении сваливается в запасной трёхсекундный таймаут:
агент начинает молчать по три секунды перед каждым ответом.

### Если бот не слышит или не отвечает

```bash
.venv/bin/python -m grainvoice.doctor
```

Проверяет микрофон, динамики, ключи и доступность голоса — и говорит, что
именно сломано, вместо гадания по логу. Ровный ноль на уровне микрофона почти
всегда означает, что macOS не дала терминалу доступ.

Проверка меряет не просто наличие сигнала, а ту же громкость по BS.1770,
по которой отсекает определитель речи в конвейере. Поэтому её вердикт
предсказывает поведение агента: «слишком тихо» означает, что собеседника
он не услышит, даже если звук в записи различим на слух.

**Лучшая связка для локального теста — встроенный микрофон плюс наушники:**

```
AUDIO_INPUT_DEVICE=Встроенный микрофон
AUDIO_OUTPUT_DEVICE=AirPods
```

Наушники обязательны: через динамики микрофон слышит голос самого агента,
распознавание его расшифровывает, и агент начинает отвечать сам себе.
Эхоподавления в локальном режиме нет; на телефонии этой проблемы не будет —
там эхо гасит сеть. Логгер такое эхо распознаёт и пишет о нём прямо,
но чинится оно только наушниками.

Микрофон гарнитуры при этом лучше не задействовать. Как только приложение
открывает его, Bluetooth переходит в режим телефонной связи: усиление падает,
и речь может не дотянуть до порога определителя. Встроенный микрофон даёт
уверенный запас, а звук всё равно идёт в наушники — эха не возникает.

Устройство задаётся номером или частью названия. Название надёжнее: нумерация
PortAudio меняется при подключении и отключении гарнитуры.

### Подробный лог

```bash
GRAINVOICE_DEBUG=1 .venv/bin/python -m grainvoice.local
```

По умолчанию в логе только разговор: `АГЕНТ:` и `ФЕРМЕР:`. Отладочный поток
Pipecat печатает системный промпт целиком перед каждым обращением к модели,
и за ним не видно ни реплик, ни ошибок.

### Если HTTPS-соединения падают

Python из Homebrew и с python.org часто идёт без привязки к системному
хранилищу корневых сертификатов. Симптом обманчив: агент не слышит
собеседника, и первая мысль — «не тот ключ». На самом деле в логах
`CERTIFICATE_VERIFY_FAILED`.

Проект подставляет набор сертификатов из `certifi` автоматически
([certs.py](voice-agent/src/grainvoice/certs.py)), но если нужно вручную:

```bash
export SSL_CERT_FILE=$(.venv/bin/python -c "import certifi; print(certifi.where())")
```

cd voice-agent && .venv/bin/python -m pytest

## Где это должно работать

**Не на macOS.** Голосовая часть требует `onnxruntime`, `aiortc` и
`cryptography`, у которых нет готовых сборок под Intel Mac — всё тянет
компиляцию с Rust-тулчейном. На Apple Silicon проще, но всё равно не путь.

Система обзвона работает круглосуточно, а ноутбук закрывают крышкой.
Телефония по SIP требует сервера со стабильным IP. Рабочая площадка —
**Linux (Ubuntu 22.04/24.04), от 2 ГБ памяти**.

Импорт и анализ звонков нативных зависимостей не имеют и работают везде,
включая macOS.

### Телефоны

В справочниках номера записаны как попало, и это единственное место, где
ошибка стоит дорого: неверный номер — либо несостоявшийся звонок, либо
звонок постороннему человеку.

Разбираемые случаи:

```
(86150) 4-45-70                стационарный с кодом города
8-918-432-0035                 мобильный
(86150) 4-50-71, 4-47-07       второй номер наследует код первого
8-800-505-0415                 федеральный — там колл-центр, отсеивается
```

Мобильные приоритизируются: на них отвечает сам глава хозяйства,
на стационарный — приёмная.

### Промпты

Промпты лежат в YAML, а не в коде — их правят чаще всего, и версия должна
быть видна в истории git отдельным изменением.

Версия — часть имени файла (`grain_buyer.v1.yaml`) и сохраняется вместе с
результатом анализа. Через полгода будет понятно, каким промптом получены
цифры в конкретной карточке.

Чтобы попробовать новый сценарий: скопируйте в `grain_buyer.v2.yaml`, правьте,
переключите `CONVERSATION_PROMPT` в `.env`. Старая версия остаётся рабочей.

## Границы агента

Агент собирает информацию и не принимает коммерческих решений. Ему запрещено
называть цену, подтверждать покупку, договариваться об объёмах и сроках,
брать обязательства от лица компании.

На вопрос «сколько дадите?» он отвечает, что передаст информацию руководителю.
Это зашито в промпт как жёсткое ограничение и покрыто тестом.

## Правовая сторона

Массовый автообзвон в РФ затрагивает 152-ФЗ (основание для обработки
персональных данных — откуда получена база) и закон «О рекламе» в части
автодозвона. При продаже продукта другим компаниям этот вопрос задаст
их юридический отдел.

Переменная `DISCLOSE_AI=true` включает честное представление агента
автоматическим помощником — на случай, если такое требование возникнет.
Переписывать код для этого не нужно.

## Секреты

Ключей в коде нет и не должно быть. `.env` в `.gitignore`, шаблон — в
`.env.example`. Записи звонков, транскрипты и выгрузки контактов содержат
персональные данные и в репозиторий не попадают.
